## 已观察的真实草稿

用户以 0.1.6 从四个微信链接发起导入。读取 B站原生编辑区确认：厉娜 50 图、19 图注；胶带 12 图、9 图注、4 公式；翻译 4 图、1 图注；问答 9 图、26 公式、0 原生图注，导航为串行代码块。问答的三条灰色图注文字仍在正文中，带面板底色；不是文字丢失。

厉娜漏删 29 张图的原因是原始懒加载图使用 `width:100%`，而本地保存网页将它写为固定像素宽。清理范围仍限定已核验素材与模板中的装饰角色，不按图片大小泛删。

从问答草稿页面实际加载的 API 响应核实：空代码语言字段会被省略；列表分组标识会被编辑器重新生成。核验现在比较列表分组关系，不比较该不透明标识本身；改字、公式变化、图片尺寸变化、代码换行变化、拆分列表等仍失败。历史 API 回归中的三个图注正文回退作为已观察差异单独建模，没有伪称旧稿具备原生图注。

B站选择文集界面显示「问答Q&A」，因此为公众号「问答」加入这一明确别名；同名匹配优先，歧义不自动选择。

## 真实 Edge 执行本地解析

用仓库的本地回归页运行 Chromium DOMParser、清理器及 Opus 转换器；网页 CSP 阻止外部资源请求，上传和一处局部转图仅使用结构占位。它验证浏览器解析差异，不等同于真实账号上传。

首轮发现纯色 `background` 简写在 Chromium 中使 `backgroundImage` 为 `initial`，而本地 DOM 库为空串，导致两类已确认装饰面板未被识别。修复只接受非继承图片属性的空、none、initial、unset；图片、渐变、inherit 不放宽。修复后五篇无格式阻断：
