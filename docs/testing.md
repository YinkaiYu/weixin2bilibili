# 测试约定

测试用于发现内容丢失和错误转换，不能靠识别样稿来获得预期结果。生产规则不得依赖测试文章的标题、全文、资源 ID 或某条公式；明确的用户规则、平台协议字段和有依据的文集映射应分别记录来源。

## 测试分层

| 层级 | 验证范围 | 不能代替的验证 |
| --- | --- | --- |
| 最小合成用例 | 解析、清理、格式转换、媒体识别和协议核验的正反例 | 未覆盖模板的实际表现 |
| 模拟接口集成 | 真实导入流程中的下载、上传、保存、读回、错误和恢复；检查最终请求数据 | B站服务端接受情况和真实页面效果 |
| 浏览器测试页 | Chromium 的样式解析、局部渲染和界面状态 | 模拟上传不能证明线上素材保真 |
| 官方协议与真实草稿 | 平台字段、链接认可情况、保存后的结构和展示 | 一次成功不能证明全部输入受支持 |
| 可选本地样稿 | 已知问题的历史回归 | 固定图数、公式数或五篇样稿通过不能证明通用性 |

运行 `npm test` 和 `npm run check`。涉及 CSS 或截图行为时，再运行 `tests/browser/` 中对应测试页；涉及线上协议时，记录官方证据或经授权的真实草稿结果。`npm run package` 单独检查分发包。公共 CI 应只依赖仓库内的合成用例；私有样稿缺失时可跳过其回归，不应跳过对应的公共最小用例。

## 新规则必须经得起内容变化

修复除原问题的回归用例外，应加入不改变语义的变形，以及相邻反例：

- 保持结构和样式，替换标题、正文、公式变量、图片地址和资源 ID，转换策略应一致，替换后的内容应完整保留。
- 使用等价 CSS 写法、中性包装和不同语言，检查规则是否依赖偶然的序列化形式。尺寸、颜色或长度阈值需说明目的，并测试边界两侧。
- 对装饰清理加入短小科学图、带图注或替代文字的图片、真实注音等反例。无法证明是装饰时应保留；不可仅为维持固定图数删除内容。
- 对协议归一化同时测试已证实的等价形式和相邻的真实变化。改一个文字、链接、颜色、公式、图片路径或分组关系，核验应能发现差异。
- 媒体集成至少使用两份不同的图片字节和上传元数据，包含重复出现；最终保存应使用上传地址、宽高和大小，保留出现顺序，不能留下预检占位值。

## 预期结果应独立于被测输出

在清理前的原始 DOM 中建立需要保留的文字、媒体出现顺序和公式基线；测试应独立列出获准删除的段落或装饰及理由，再检查保留内容。不要从已经清理后的 DOM 重新生成预期清单，随后以两者相同证明清理没有错删。统计数量只能作为辅助，还需检查身份、顺序、内容和格式。

模拟保存后原样返回请求，可以验证流程和恢复逻辑，不能证明平台会原样保存。历史草稿缺少原始上传请求时，若用回读结果补齐图片地址或尺寸，必须说明该用例只检查其余可独立核对的字段；不得据此声称图片身份或端到端保真已经验证。

本地完整文章、截图、接口响应和账号数据放在已忽略的目录，不提交仓库。把已发现问题提炼成最小合成用例，并用未参与制定规则的输入检查泛化；不要通过修改样稿或期望值掩盖新的内容损失。
